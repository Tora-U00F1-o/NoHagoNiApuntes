pizzas-modelar-con-atributos§Elementos y atributos§En el ejemplo de pizzas, nombre y precio se almacenan como atributos.§Los atributos de pizza son siempre nodos hijo ingrediente.§Se lee pizza nombre="Barbacoa" precio="8,0€".§Nombre y precio son atributos de pizza.§Nombre y precio son necesariamente elementos anidados.
poema-texto-en-elementos-y-metadatos-en-atributos§Texto del poema§El ejemplo del poema usa texto en elementos y metadatos en atributos.§Un elemento XML no puede contener texto.§Un verso conserva su contenido como texto del elemento.§El modelo es coherente con el ejemplo del poema.§Debe transformarse obligatoriamente en un atributo para ser XML.
libros-repeticion-y-opcionalidad§Modelado de libros§La colección de libros ilustra elementos repetidos y datos opcionales.§El modelo XML prohíbe que dos hermanos tengan el mismo nombre.§Una colección incluye varios elementos libro.§La repetición de nombres entre hermanos es posible.§La repetición demuestra por sí sola mala formación.
visualizar-arboles-con-xml2svg§Visualización§xml2svg genera una representación gráfica del árbol; verla no sustituye validar una gramática.§Un dibujo del árbol demuestra conformidad con cualquier XSD.§Un archivo produce un dibujo legible, sin comprobarse su DTD.§No se ha demostrado validez respecto de esa DTD.§La generación de SVG acredita toda restricción de la DTD.
kml-y-kmz§KML§KML es un vocabulario XML de información geográfica.§KML es exclusivamente una hoja de estilos tipográficos.§Se necesita representar puntos y rutas geográficas en el vocabulario del material.§KML es el vocabulario pertinente.§WaterML se presenta como el vocabulario general de rutas KML.
kml-y-kmz§KMZ§KMZ empaqueta contenido KML mediante ZIP.§KMZ es el nombre del algoritmo que convierte XML en HTML.§Un archivo geográfico del ejemplo se distribuye comprimido como KMZ.§El empaquetado corresponde a ZIP con contenido KML.§La extensión implica que ya no puede contener KML.
svg-y-graficos-vectoriales§SVG§SVG describe gráficos vectoriales bidimensionales, incluidos formas y texto.§SVG es un formato exclusivo de mapas de bits sin elementos XML.§Un dibujo se describe con círculos, rectángulos y texto XML.§Encaja en el uso de SVG del material.§Debe almacenarse como una imagen de píxeles para poder ser SVG.

prologo-cuerpo-y-comentarios§Declaración XML§version, encoding y standalone describen versión, codificación y dependencia de declaraciones externas.§standalone indica el número de hijos permitido por la raíz.§Se interpreta encoding="UTF-8" como una restricción de cardinalidad.§Encoding identifica codificación, no frecuencia de elementos.§UTF-8 significa exactamente ocho elementos obligatorios.
prologo-cuerpo-y-comentarios§Comentarios§Los comentarios XML no se anidan y no pueden contener la secuencia --.§Un comentario XML admite cualquier cantidad de -- en su interior.§Se inserta -- dentro del texto de un comentario.§Se incumple una restricción sintáctica de comentarios.§Es siempre texto permitido dentro del comentario.
elementos-y-atributos§Raíz única§Un documento XML bien formado tiene un único elemento documento.§Dos elementos raíz hermanos son válidos en cualquier documento XML completo.§El archivo completo contiene únicamente <a/><b/>.§No cumple la condición de raíz única de un documento XML.§Cumple la raíz única porque ambos elementos están vacíos.
elementos-y-atributos§Anidamiento§Las etiquetas XML deben cerrarse y anidarse correctamente.§XML acepta cerrar elementos en cualquier orden si aparecen todos los nombres.§Se escribe <a><b></a></b>.§Los cierres se cruzan y el documento no está bien formado.§Está bien formado porque ambos nombres tienen cierre.
elementos-y-atributos§Mayúsculas§Los nombres XML distinguen mayúsculas y minúsculas.§<Libro> y <libro> son siempre el mismo nombre XML.§Se abre <Libro> y se cierra </libro>.§Los nombres no coinciden para formar el cierre.§El cierre es correcto porque XML ignora mayúsculas.
elementos-y-atributos§Nombres§Los nombres de elementos XML no pueden contener espacios.§Un nombre XML puede incluir libremente un espacio entre dos palabras.§Se intenta usar nombre completo como un solo nombre de elemento.§El espacio impide tratarlo como nombre XML válido.§El espacio es un carácter ordinario del nombre.
elementos-y-atributos§Comillas de atributos§Los valores de atributos XML se delimitan con comillas.§Las comillas de los valores XML son siempre opcionales como en ciertos casos HTML.§Se escribe <libro id=uno/>.§El valor del atributo carece de las comillas exigidas.§Es XML bien formado por ser el valor una sola palabra.
elementos-y-atributos§Unicidad de atributos§Un elemento no puede repetir el mismo nombre de atributo.§XML admite repetir un atributo para que prevalezca su último valor.§Se escribe <a id="x" id="y"/>.§La repetición del atributo impide buena formación.§Es correcto y el valor efectivo debe ser y.
elementos-y-atributos§Orden de atributos§Cambiar el orden de atributos no cambia su significado como atributos XML.§Cambiar el orden de los atributos cambia necesariamente la jerarquía de hijos.§Se intercambian nombre y precio en la etiqueta de apertura de pizza.§No cambia por ello la jerarquía del árbol.§Convierte el segundo atributo en elemento hijo.
elementos-y-atributos§Atributos xml§xml:lang indica idioma, xml:space tratamiento de espacios y xml:base base de rutas.§xml:base indica el tamaño en bytes del archivo XML.§Se necesita especificar la base usada para resolver rutas relativas.§El atributo pertinente es xml:base.§El atributo pertinente es necesariamente xml:lang.
entidades-procesamiento-y-cdata§Entidades predefinidas§XML incluye amp, lt, gt, apos y quot como entidades predefinidas.§XML incluye nbsp entre sus cinco entidades predefinidas.§Se requiere escribir un ampersand literal escapado en texto XML.§Puede utilizarse &amp;.§Debe utilizarse exclusivamente &nbsp;.
entidades-procesamiento-y-cdata§CDATA§Una sección CDATA permite escribir texto con caracteres de marcado sin interpretarlos como etiquetas.§CDATA crea elementos hijo a partir de cada etiqueta escrita en su interior.§Se coloca x < 3 && y > 4 dentro de CDATA.§El contenido se trata como texto.§El símbolo < inicia necesariamente un elemento dentro de CDATA.
buena-formacion-y-validez§Buena formación§La buena formación comprueba sintaxis XML; la validez añade conformidad con una gramática.§Un archivo sintácticamente correcto satisface automáticamente cualquier DTD.§Un XML tiene raíz única y cierres correctos, pero incumple la DTD declarada.§Puede estar bien formado y no ser válido.§Debe ser válido porque las etiquetas cierran correctamente.
buena-formacion-y-validez§Validez§Ser válido exige primero buena formación y después las restricciones de DTD o Schema.§Un documento mal formado puede ser válido respecto de su DTD.§Un archivo omite un cierre pero sus nombres aparecen en la DTD.§La gramática no subsana la mala formación.§La coincidencia de nombres basta para validar el archivo.
ventajas-y-limitaciones§Costes y ejecución§XML favorece intercambio y legibilidad, pero puede ser verboso; describir un programa no lo ejecuta.§Todo programa descrito como XML se ejecuta automáticamente al abrir el documento.§Un archivo XML describe operaciones pero no existe intérprete que las ejecute.§La descripción por sí sola no realiza las operaciones.§El marcado ejecuta las operaciones sin procesamiento adicional.
